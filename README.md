# «Барометр» — PO Copilot

Рабочее пространство продакт-оунера: аналитика продукта, задачи и ИИ-ассистент в одном интерфейсе.
Прототип на моковых данных — интерфейс полный и рабочий, источники данных пока фикстуры.

## Первый запуск в новом контуре

Пройти сверху вниз. Пункты 1–3 обязательны, без них ассистент не заработает.

- [ ] **1. Поднять модель за OpenAI-совместимым API.** Проверено на vLLM ≥ 0.19 с Qwen.
- [ ] **2. Включить вызов инструментов при запуске vLLM:** `--enable-auto-tool-choice`
      и `--tool-call-parser` под модель (для Qwen — `hermes`).
      ⚠️ **Без этого ассистент выглядит рабочим, но бесполезен:** отвечает связно и
      уверенно, при этом «из головы» — без метрик, без создания задач, без карточек.
      Проверять в первую очередь.
- [ ] **3. Заполнить `.env.local`** по `.env.example`. Обязательны: `APP_LOGIN`,
      `APP_PASSWORD`, `APP_SESSION_SECRET`, `AI_BASE_URL`, `AI_MODEL`.
      ⚠️ `AI_BASE_URL` указывается **вместе с `/v1`, но без `/chat/completions`**.
      `AI_API_KEY` можно оставить пустым — локальный vLLM обычно без авторизации.
      ⚠️ За nginx или ingress выставить `TRUST_PROXY=1`, иначе в аудит-логе окажется
      адрес прокси вместо адреса пользователя.
- [ ] **4. Проверить reasoning-parser.** Если модель умеет размышлять, парсер должен
      быть включён — иначе рассуждения полезут в чат. Сервер дополнительно вырезает
      `<think>…</think>`, но это страховка, а не замена настройке.
- [ ] **5. Проверить `AI_VISION`.** По умолчанию `false` — картинки заменяются пометкой.
      Включать **только** если модель мультимодальная (VL), иначе запрос вернёт 400.
- [ ] **6. Если tool-парсер плохо работает в стриминге** — выключить `AI_STREAM`.
      Ответ придёт целиком вместо печати по буквам, остальное продолжит работать.
- [ ] **7. Веб-поиск.** Инструмент `search_web` ходит в Brave через интернет. В закрытом
      контуре он недоступен — без ключа возвращает пустой результат и НЕ падает.
      Если поиск нужен, подменить на внутренний источник в `src/lib/tools.ts`.
- [ ] **8. Данные.** Всё, что показывает интерфейс, — фикстуры из `src/data/fixtures/`.
      Подключение реальных источников (Jira, Confluence, Git, метрики) не начиналось.

### Диагностика при первом запуске

```bash
# 1. Доступна ли модель
curl -s "${AI_BASE_URL}/chat/completions" -H "content-type: application/json" \
  -d "{\"model\":\"${AI_MODEL}\",\"max_tokens\":10,\"messages\":[{\"role\":\"user\",\"content\":\"test\"}]}"

# 2. Умеет ли она вызывать инструменты (главная проверка)
curl -s "${AI_BASE_URL}/chat/completions" -H "content-type: application/json" -d "{
  \"model\":\"${AI_MODEL}\",\"max_tokens\":100,
  \"messages\":[{\"role\":\"user\",\"content\":\"какие метрики у продукта?\"}],
  \"tools\":[{\"type\":\"function\",\"function\":{\"name\":\"get_metrics\",
    \"description\":\"метрики продукта\",\"parameters\":{\"type\":\"object\",\"properties\":{}}}}]}"
# В ответе должен быть tool_calls. Если вместо него обычный текст —
# vLLM запущен без --enable-auto-tool-choice.

# 3. Живо ли приложение
curl -s http://localhost:3001/api/health
```

## Переменные окружения

Все переменные читаются API-сервером (`scripts/api-server.ts`).
Фронтенду переменные не нужны — ключи никогда не попадают в браузер.

Файл `.env.local` (в `.gitignore`, **никогда не коммитить**). Шаблон — `.env.example`.

### Авторизация — обязательно

| Переменная | Назначение | Пример |
|------------|-----------|--------|
| `APP_LOGIN` | Логин. Проверяется только на сервере, эндпоинт `POST /api/auth` | `product-owner` |
| `APP_PASSWORD` | Пароль к этому логину | `<длинная случайная строка>` |
| `APP_SESSION_SECRET` | Секрет для HMAC-SHA256 подписи сессионных токенов. При смене все выданные токены инвалидируются | `<32+ случайных символов>` |

Без этих трёх `/api/auth` вернёт 500, войти в приложение будет нельзя. `APP_SESSION_SECRET`
проверяется и на `/api/chat`, и на `/api/search` — запросы без валидного токена отклоняются.

### Модель — обязательно для ассистента

| Переменная | Обяз. | Назначение | Пример |
|------------|-------|-----------|--------|
| `AI_BASE_URL` | да | Адрес OpenAI-совместимого API. Без него `/api/chat` вернёт 500 с прямым указанием на переменную | `http://llm-host:8000/v1` |
| `AI_MODEL` | да | Имя модели на сервере инференса (для vLLM — `--served-model-name`) | `qwen3-32b` |
| `AI_API_KEY` | нет | Ключ API. Локальный vLLM обычно без авторизации — тогда пусто | — |

⚠️ `AI_BASE_URL` указывается **вместе с `/v1`, но без `/chat/completions`** — суффикс
добавляет клиент. Ошибка здесь даёт 404 при первом же сообщению в чат.

Поведение модели настраивается тремя флагами:

| Переменная | По умолч. | Что делает |
|------------|-----------|------------|
| `AI_VISION` | `false` | Распознаёт ли модель картинки. При `false` вложенные изображения заменяются текстовой пометкой. Включать **только** для мультимодальных моделей (VL) — иначе сервер ответит 400 |
| `AI_STREAM` | `true` | Печать ответа по буквам. Выключить, если tool-парсер vLLM неверно работает в стриминге: ответ придёт целиком, остальное продолжит работать |
| `AI_ENABLE_THINKING` | `false` | Режим размышлений Qwen (`chat_template_kwargs.enable_thinking`). Заметно увеличивает время ответа и занимает слоты инференса |

### Веб-поиск — опционально

| Переменная | Назначение |
|------------|-----------|
| `BRAVE_SEARCH_API_KEY` | Ключ Brave Search API, эндпоинт `/api/search`, инструмент `search_web`. Без него поиск возвращает пустой результат с пояснением — приложение не падает |
| `BRAVE_PROXY_URL` | Прокси для Brave (суффикс `/brave`). По умолчанию `https://api.search.brave.com` |

### Аудит-лог

| Переменная | Назначение | По умолчанию |
|------------|-----------|--------------|
| `AUDIT_LOG_FILE` | Файл журнала изменений конфигурации (JSON Lines). Если не задан — журнал идёт в stdout с полем `kind:"audit"` | stdout |
| `TRUST_PROXY` | Включить, если приложение стоит за nginx или ingress: иначе в поле `ip` аудита попадёт адрес прокси, а не пользователя. Без прокси **не включать** — `X-Forwarded-For` подделывается | выключено |

### Прочее

| Переменная | Назначение | По умолчанию |
|------------|-----------|--------------|
| `PROXY_SECRET` | Заголовок `x-proxy-secret` для защищённого прокси. Нужен, только если задан `BRAVE_PROXY_URL` | — |
| `PORT` | Порт API-сервера | `3001` (`npm start` использует `3002`) |

## Требования к серверу модели

Проверено на vLLM ≥ 0.19 с Qwen. Два условия, без которых ассистент выглядит рабочим,
но бесполезен — он будет отвечать связно и **из головы**, без данных продукта:

1. **Вызов инструментов должен быть включён.** vLLM запускается с
   `--enable-auto-tool-choice` и `--tool-call-parser` под конкретную модель (для Qwen —
   `hermes`). Без этого модель не сможет вызвать ни одну функцию приложения.
2. **Reasoning-parser** — если модель умеет размышлять, парсер должен быть включён,
   тогда рассуждения приходят отдельным полем и не попадают в чат. На случай запуска
   без парсера сервер дополнительно вырезает блоки `<think>…</think>` из текста.

Если tool-парсер некорректно отдаёт вызовы в потоковом режиме — выключите `AI_STREAM`.

## Известные ограничения

| Что | Подробности |
|-----|-------------|
| **Документы во вложениях** | PDF/Word/Excel модели **не передаются** — в OpenAI-совместимом API нет типа «документ», а веб-интерфейсы, которые «умеют PDF», разбирают файл у себя и подмешивают текст в промпт. Уходит честная пометка с именем файла и запретом выдумывать содержимое. Текстовые файлы и JSON читаются полностью. Точка встраивания извлечения помечена `TODO` у `FilePart` в `scripts/lib/ai-protocol.ts`, base64 файла уже приходит на сервер |
| **`finish_reason` от vLLM** | Часть tool-парсеров отдаёт `stop` даже при наличии вызовов инструментов. Код опирается на **наличие вызовов**, а не на причину завершения. Не «чинить» это при рефакторинге — агентный цикл оборвётся молча |
| **Типы протокола продублированы** | Нейтральные типы описаны и в `src/lib/ai.ts`, и в `scripts/lib/ai-protocol.ts`. TypeScript их не связывает — расхождение поймает сквозной тест `scripts/api-server.test.ts`, но не компилятор |
| **Оборванный JSON аргументов** | Инструмент получает пустой ввод, в лог сервера пишется предупреждение |
| **Кэширование промптов** | Своего механизма нет, его роль берёт prefix caching сервера инференса. Волатильное (дата, имя пользователя) не должно попадать в начало системного промпта, иначе префикс «плывёт» и кэш промахивается |
| **Аудит-лог — каркас** | Слой пишет события, но аккаунт один на всех, поэтому `actor` у всех записей одинаковый. Полноценным журнал станет с аутентификацией пользователей. Подробнее — раздел «Аудит-лог» |
| **`AIPanelSider.tsx` — 2340 строк** | Агентный цикл, вызовы инструментов, вложения и рендер восьми типов блоков в одном файле. Главный кандидат на декомпозицию |
| **ESLint — 16 замечаний** | В основном `setState` внутри эффектов. Предсуществующие, не чинились сознательно |
| **Расхождение в unit-экономике** | KPI «Срок окупаемости» считается как `CAC/CM`, а точка на графике — с учётом оттока. Не сведено |
| **Нет серверного хранилища** | Состояние живёт в браузере (Zustand + localStorage). Для многопользовательского режима нужна БД |
| **Тестами покрыт ИИ-слой, не интерфейс** | 139 тестов — транспорт, конвертация, промпты, инструменты, аудит. Компонентных тестов нет |

## Аудит-лог (требование ИБ)

Изменения конфигурации журналируются отдельно от обычных логов приложения: у аудита
другой срок хранения, другие требования к целостности и другие читатели. Формат —
JSON Lines, одна строка на событие, напрямую пригодно для приёма в ELK/Splunk.

```json
{"kind":"audit","ts":"2026-07-29T14:32:10.001Z","actor":"product-owner","action":"settings.theme.change","target":"settings.theme","before":"dark","after":"light","ip":"10.0.0.7"}
```

Как устроено:

- интерфейс вызывает `recordAudit()` из `src/lib/audit.ts`;
- сервер принимает событие на `POST /api/audit` и пишет его через `scripts/lib/audit.ts`;
- **субъект и время проставляет сервер**: `actor` берётся из сессионного токена, время —
  своё. Значения этих полей из тела запроса игнорируются, иначе их можно подделать;
- значения полей, похожих на секреты (`password`, `token`, `apiKey` и т.п.), заменяются
  на `[скрыто]` на любой глубине вложенности;
- `action` проверяется по контролируемому словарю `AUDIT_ACTIONS`. Неизвестное действие
  отклоняется с 400 — чтобы в журнал не попадали опечатки и мусор. **Добавляя новое
  событие в интерфейсе, сначала внесите его в этот список.**

⚠️ **За nginx или ingress обязательно выставить `TRUST_PROXY=1`.** Иначе в поле `ip`
каждого события окажется адрес прокси, и журнал не позволит установить, откуда
пришло действие.

⚠️ **Это каркас, а не готовая подсистема.** В прототипе аккаунт один на всех, поэтому
`actor` у всех событий одинаковый — полноценным журнал станет с появлением
аутентификации пользователей. Подключена одна реально существующая точка изменения
настроек (переключение темы, `src/store/themeStore.ts`) — как рабочий образец;
остальные разделы настроек пока заглушки, при их реализации вызов `recordAudit`
добавляется по тому же шаблону.

⚠️ Неудачная запись в журнал сейчас **не отменяет** само изменение настройки. Если ИБ
потребует «без записи в журнал изменение не применяется», менять надо в двух местах:
`writeAuditEvent` на сервере и `recordAudit` на клиенте — сделать вызов блокирующим
и откатывать действие при ошибке.

## Правила кода

Соглашения, принятые в проекте. Держитесь их, чтобы код оставался однородным.

- **Дизайн-система — antd v5**, обе темы (`ConfigProvider` + `theme.darkAlgorithm` /
  `defaultAlgorithm`). Других UI-библиотек нет. Стилизация — через design tokens,
  не произвольным CSS.
- **Язык интерфейса — русский.** Комментарии в коде тоже.
- **TypeScript строгий, `any` запрещён.** Типы домена — в `src/data/types/`.
- **Одна фича — одна папка** в `src/features/`.
- **Данные только через `src/data/api/`**, не из фикстур напрямую.
- **Цвета рисков** — токены `colorError` / `colorWarning` / `colorSuccess`, не хардкод.
- **Системные промпты — в `src/skills/`**, по файлу на агента или сценарий
  (см. `src/skills/README.md`). Новое действие аудита сначала вносится
  в словарь `AUDIT_ACTIONS`.
- Перед коммитом — `npm run typecheck`, `npm run lint`, `npm run test`.

## ИИ-ассистент

Браузер отправляет диалог на `POST /api/chat` в нейтральных типах приложения
(`src/lib/ai.ts`) и не знает, какой провайдер модели стоит за эндпоинтом. Конвертацию
в формат провайдера и обратно делает сервер (`scripts/lib/ai-protocol.ts`) — он же
собирает вызовы инструментов из потока и отдаёт их браузеру готовыми. Смена провайдера
затрагивает только этот файл.

Ассистент работает как оркестратор со специалистами
(`src/lib/specialists.ts`): интерактивный сбор требований идёт у оркестратора, тяжёлое
исполнение — у stateless-специалиста по готовому ТЗ. Инструменты (`src/lib/tools.ts`)
читают те же моковые данные, что и UI, и умеют создавать черновики задач, CJM и артефакты
базы знаний.

Системные промпты — папка `src/skills/` (по файлу на агента и сценарий, см. её README).
Подробное описание принципа работы
агентов (кто за что отвечает, как добавить специалиста, что легко сломать) —
`docs/agents.md`.

## Docker

Один контейнер отдаёт и собранный интерфейс, и API — отдельный веб-сервер не нужен.

```bash
docker build -t po-copilot .
docker run -p 3001:3001 --env-file .env.local po-copilot
```

Приложение открывается на `http://localhost:3001`. Секреты в образ не зашиваются —
переменные передаются при запуске. Проба живости для оркестраторов: `GET /api/health`.

Образ двухстадийный: стадия сборки ставит все зависимости и собирает `dist/`,
в рантайм попадают только `dist/`, `scripts/` и продакшн-зависимости — исходники `src/`
и инструменты сборки в образ не входят.

## Развёртывание без Docker

Если контейнер не подходит, приложение запускается процессом под PM2:

```bash
npm ci && npm run build
pm2 start ecosystem.config.cjs
```

Процесс `po-copilot-api` слушает порт 3001 и отдаёт и API, и статику из `dist/` —
отдельный веб-сервер не обязателен. Если он всё же ставится впереди (терминация TLS,
общий вход), не забудьте `TRUST_PROXY=1`, иначе в аудит-логе окажется адрес прокси.

Пути в `ecosystem.config.cjs` и `scripts/start-api.sh` вычисляются от расположения
файлов — привязки к конкретной машине нет. Переменные окружения читаются
из `.env.local` рядом с проектом.

Автоматической доставки в репозитории нет: настройте её под правила своего контура.

## Что не решено

- Веса формулы скоринга бэклога (ICE/RICE + compliance + стратегия).
- Хранилище и индексация графа знаний.
- Требования банка по срокам хранения и транспорту аудит-событий — уточнить у ИБ.
- Попадают ли под требование аудита действия, которые ассистент совершает от имени
  пользователя (создание черновика задачи, генерация CJM, сохранение артефакта).
  Технически подключается так же — вызовом `recordAudit` в местах выполнения
  инструментов в `src/lib/tools.ts`. Решение за принимающей стороной: объём журнала
  меняется в разы.
- Постоянное хранилище и аутентификация пользователей — от них зависит и аудит,
  и многопользовательский режим.
