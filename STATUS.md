## 1. Что нужно настроить в контуре — чек-лист

Пройти сверху вниз. Пункты 1–3 обязательны, без них ассистент не заработает.

- [ ] **1. Поднять модель за OpenAI-совместимым API.** Проверено на vLLM ≥ 0.19 с Qwen.
- [ ] **2. Включить вызов инструментов при запуске vLLM:** `--enable-auto-tool-choice`
      и `--tool-call-parser` под модель (для Qwen — `hermes`).
      ⚠️ **Без этого ассистент выглядит рабочим, но бесполезен:** отвечает связно и
      уверенно, при этом «из головы» — без метрик, без создания задач, без карточек.
      Это главная мина переноса, проверять в первую очередь.
- [ ] **3. Заполнить `.env.local`** по `.env.example`. Обязательны: `APP_LOGIN`,
      `APP_PASSWORD`, `APP_SESSION_SECRET`, `AI_BASE_URL`, `AI_MODEL`.
      ⚠️ `AI_BASE_URL` указывается **вместе с `/v1`, но без `/chat/completions`**.
      `AI_API_KEY` можно оставить пустым — локальный vLLM обычно без авторизации.
- [ ] **4. Проверить reasoning-parser.** Если модель умеет размышлять, парсер должен
      быть включён — иначе рассуждения полезут в чат. Сервер дополнительно вырезает
      `<think>…</think>`, но это страховка, а не замена настройке.
- [ ] **5. Проверить `AI_VISION`.** По умолчанию `false` — картинки заменяются пометкой.
      Включать **только** если модель мультимодальная (VL), иначе запрос вернёт 400.
- [ ] **6. Если tool-парсер плохо работает в стриминге** — выключить `AI_STREAM`.
      Ответ придёт целиком вместо печати по буквам, остальное продолжит работать.
- [ ] **7. Веб-поиск.** `search_web` ходит в Brave через интернет. В закрытом контуре
      он недоступен — без ключа инструмент возвращает пустой результат и НЕ падает.
      Если поиск нужен, подменить на внутренний источник в `src/lib/tools.ts`.
- [ ] **8. Данные.** Всё, что показывает интерфейс, — фикстуры из `src/data/fixtures/`.
      Подключение реальных источников (Jira, Confluence, Git, метрики) — не начиналось.

### Диагностика при первом запуске

```bash
# 1. Доступна ли модель
curl -s "${AI_BASE_URL}/chat/completions" -H "content-type: application/json" \
  -d "{\"model\":\"${AI_MODEL}\",\"max_tokens\":10,\"messages\":[{\"role\":\"user\",\"content\":\"test\"}]}"

# 2. Умеет ли она вызывать инструменты (главная проверка)
curl -s "${AI_BASE_URL}/chat/completions" -H "content-type: application/json" -d "{
  \"model\":\"${AI_MODEL}\",\"max_tokens\":100,
  \"messages\":[{\"role\":\"user\",\"content\":\"какие метрики у продукта?\"}],
  \"tools\":[{\"type\":\"function\",\"function\":{\"name\":\"get_metrics\",
    \"description\":\"метрики продукта\",\"parameters\":{\"type\":\"object\",\"properties\":{}}}}]}"
# В ответе должен быть tool_calls. Если вместо него обычный текст —
# vLLM запущен без --enable-auto-tool-choice.

# 3. Живо ли приложение
curl -s http://localhost:3001/api/health
```

## 2. Известные ограничения и мины

| Что | Подробности |
|-----|-------------|
| **Документы во вложениях** | PDF/Word/Excel модели **не передаются** — в OpenAI-совместимом API нет типа «документ». Уходит честная пометка с именем файла и запретом выдумывать содержимое. Текстовые файлы и JSON читаются полностью. Точка встраивания извлечения помечена `TODO` у `FilePart` в `scripts/lib/ai-protocol.ts`, base64 файла уже приходит на сервер |
| **`finish_reason` от vLLM** | Часть tool-парсеров отдаёт `stop` даже при наличии вызовов. Код опирается на **наличие вызовов**, а не на причину завершения. Не «чинить» это при рефакторинге — цикл ассистента оборвётся молча |
| **Типы протокола продублированы** | Нейтральные типы описаны и в `src/lib/ai.ts`, и в `scripts/lib/ai-protocol.ts`. TypeScript их не связывает — расхождение поймает сквозной тест `scripts/api-server.test.ts`, но не компилятор |
| **Оборванный JSON аргументов** | Инструмент получает пустой ввод (поведение сохранено от прежней реализации), в лог сервера пишется предупреждение |
| **Кэширование промптов** | Прежний механизм снят вместе с Anthropic. Его роль берёт prefix caching сервера инференса. Волатильное (дата, имя пользователя) не должно попадать в начало системного промпта, иначе префикс «плывёт» и кэш промахивается |
| **`AIPanelSider.tsx` — 2340 строк** | Агентный цикл, вызовы инструментов, вложения и рендер ~8 типов блоков в одном файле. Главный кандидат на декомпозицию |
| **ESLint — 16 замечаний** | Предсуществующие, в основном `setState` внутри эффектов. В новом коде чисто |
| **Расхождение в unit-экономике** | KPI «Срок окупаемости» считается как `CAC/CM`, а точка на графике — с учётом оттока. Не сведено |

## 4. Архитектура ИИ-ассистента

**Поток запроса.** Браузер (`src/lib/ai.ts`) шлёт диалог в нейтральных типах приложения
на `POST /api/chat`. Сервер (`scripts/lib/ai-protocol.ts`) переводит это в формат
OpenAI, вызывает модель, собирает вызовы инструментов из потока и отдаёт браузеру
готовыми. **Это единственное место, знающее формат провайдера** — смена модели
затрагивает только его.

**Оркестратор и специалисты.** Главный цикл в `AIPanelSider.tsx` — оркестратор: он
владеет диалогом и интерактивным сбором требований. Тяжёлое исполнение делегируется
специалисту (`src/lib/specialists.ts`) — stateless-исполнителю, вызываемому как
инструмент по готовому ТЗ. Так закрыт баг «специалист задаёт вопрос и теряет
состояние». Инструмент `create_task_draft` принадлежит **только** специалисту —
поэтому карточка черновика появляется при любом сценарии.

**Инструменты** — 16 базовых (`src/lib/tools.ts`) + 9 специалистов. Модели за раз
уходит 24. Читающие берут данные из тех же фикстур, что и интерфейс.

**Архитектура переписана и работает** — переход на оркестратор и специалистов
завершён, все девять доменов переведены. Отдельной «будущей переработки» в планах
нет. Подробное описание принципа работы — `agent-architecture-notes.txt`.

**Что осталось проверить, а не переделать:** схема делает несколько обращений к
модели на одну реплику пользователя (ход оркестратора → раунды специалиста →
финальный ход). На облачном API это незаметно, на своём сервере инференса — это
занятые слоты. Пропускную способность стоит померить до раскатки на всех продактов;
если упрётся, сокращать надо будет именно число обращений.

## 6. Передача проекта

**Стратегия.** Разработчик получает **отдельный репозиторий** (снимок этой ветки как
его `main`), а не доступ к исходному репо: там `main` деплоится на боевой VPS владельца,
и GitHub Secrets в новый репозиторий не наследуются. Ветка в `main` исходного репо
**не мержится** — исходный `main` остаётся рабочим демо на Anthropic.

**Никакие секреты передавать не нужно.** Ключи Anthropic и прокси ушли вместе со
сменой провайдера; доступы к VPS — это деплой владельца; `APP_SESSION_SECRET`
принимающая сторона генерирует себе сама. Логин и пароль прототипа задаются в их
собственном `.env.local` — передавать нечего.

**Гигиена перед передачей (обязательный отдельный проход):**

- [x] Логин и пароль прототипа удалены из текущих файлов (были только в `STATUS.md`).
- [x] `agent-architecture-notes.txt` переписан: вместо истории обсуждений — описание
      принципа работы агентов. Файл остаётся в передаваемой копии.
- [ ] Вычистить из `CLAUDE.md` инфраструктуру владельца: IP VPS, домен,
      URL Cloudflare Worker, имя личного репозитория прокси → плейсхолдеры.
- [ ] Убрать `.github/workflows/deploy.yml` — он про VPS владельца.
- [ ] Проверить, что `.env.local` не попал в репозиторий (покрыт `.gitignore`).
- [ ] **В самом конце:** схлопнуть историю git в один начальный коммит.
      Иначе в передаваемый репозиторий уедут старые версии `STATUS.md` с паролем
      прототипа, IP и доменом — вычистка текущих файлов от этого не спасает.

push тегов из среды агента заблокирован, коммит `3fb8b55` и так остаётся головой `main`.

**E1 — переименование сервера.** `scripts/dev-api-server.ts` → `scripts/api-server.ts`
(`git mv`, история файла сохранена), обновлены все ссылки. **README переписан с нуля** —
был дефолтным шаблоном Vite.

**ИИ-слой переведён на OpenAI-совместимый API** — жёсткая замена, `@anthropic-ai/sdk`
удалён, добавлен `openai@^7`. Вся конвертация на сервере; браузер провайдера не знает.
Учтено: признак раунда с инструментами по наличию вызовов, а не по `finish_reason`;
результаты инструментов отдельными сообщениями `role:'tool'` с принудительной починкой
парности; сборка потоковых `tool_calls` по `index` с тремя вариантами поведения серверов
по имени; снят `cache_control`; игнорируется `reasoning_content` и вырезаются `<think>`;
ошибки размаплены в понятные сообщения с подсказками по переменным; запрос к модели
отменяется при обрыве соединения. Ключ схемы инструментов переименован
`input_schema` → `parameters` (25 определений).

**Docker.** Multi-stage `Dockerfile`: сборка → рантайм только с продакшн-зависимостями.
Один контейнер отдаёт и SPA, и API — отдельный nginx не нужен. Добавлены `/api/health`
для проб живости и раздача статики с фолбэком на `index.html` (пути `/api/` при этом
дают честную 404, а не страницу приложения). `express` и `tsx` перенесены из
`devDependencies` в `dependencies` — иначе `npm ci --omit=dev` в образе не поднял бы
сервер. Образ здесь не собирался (реестр недоступен из среды агента), но рантайм-стадия
воспроизведена вручную: `npm ci --omit=dev` + `scripts/` + `dist/` — сервер стартует,
проба живости, SPA и клиентские роуты отвечают.

**Побочная находка:** папка `scripts/` **никогда не покрывалась `typecheck`** — в
`tsconfig.node.json` был только `vite.config.ts`. Включена со `strict`, вскрылись и
исправлены две типовые ошибки в модуле токенов (логика не менялась).

**Тесты: 114 вместо 4.** Юниты на конвертацию, сборку вызовов, фильтр размышлений,
